# 채비 피드백 검토 보고서

상태: `DRAFT`

> 이 문서는 사용자가 직접 내보낸 구조화 피드백을 검토하기 위한 템플릿이다. 원본 JSON은 저장소에 커밋하지 않는다.

## 1. 검토 정보

| 항목 | 값 |
|---|---|
| 검토 ID | `[예: FR-2026-001]` |
| 검토일 | `[YYYY-MM-DD]` |
| 검토자 | `[이름 또는 역할]` |
| 검토 기간 | `[시작일 ~ 종료일]` |
| 입력 JSON 수 | `[0]` |
| 적용 스키마 | `[schemaVersion: 1]` |
| 포함 규칙 버전 | `[예: v0.3]` |

## 2. 개인정보·범위 확인

- [ ] 원본 JSON은 저장소 밖의 승인된 로컬 위치에서만 읽었다.
- [ ] 작업·목표 원문을 추가로 결합하지 않았다.
- [ ] 이메일, 계정 ID, 토큰, 비공개 URL 등 민감정보가 보고서에 없다.
- [ ] route와 discover를 분리해 집계했다.
- [ ] 서로 다른 `rulesVersion`을 하나의 정확도 수치로 합치지 않았다.
- [ ] 이 검토가 코드 변경, GitHub 반영, Sites 배포를 자동 승인하지 않음을 확인했다.

## 4. 버전·모드별 요약

| rulesVersion | mode | 전체 | helpful | not_helpful | 참고 |
|---|---|---:|---:|---:|---|
| `[v0.3]` | `[route]` | `[0]` | `[0]` | `[0]` | |
| `[v0.3]` | `[discover]` | `[0]` | `[0]` | `[0]` | |

> helpful 비율은 자발적 소규모 표본의 기술 통계일 뿐 제품 정확도나 성공률이 아니다.

## 5. not_helpful 사유별 신호

| 사유 | 수량 | 주 모드 | 반복 추천 요약 | 판정 |
|---|---:|---|---|---|
| `wrong_category` | `[0]` | discover | `[없음]` | `[SIGNAL / 해당 없음]` |
| `wrong_order` | `[0]` | discover | `[없음]` | `[SIGNAL / 해당 없음]` |
| `wrong_ai_model` | `[0]` | route | `[없음]` | `[SIGNAL / 해당 없음]` |
| `wrong_plugin` | `[0]` | route | `[없음]` | `[SIGNAL / 해당 없음]` |
| `unclear_result` | `[0]` | route/discover | `[없음]` | `[SIGNAL / 해당 없음]` |

## 6. 검토 후보 목록

| 후보 ID | mode | 사유 | rulesVersion | 관련 피드백 ID | 상태 | 다음 증거 |
|---|---|---|---|---|---|---|
| `[SIG-001]` | `[route/discover]` | `[고정 사유]` | `[버전]` | `[ID 목록]` | `SIGNAL` | `[익명화 재현 사례 필요]` |

관련 피드백 ID는 구조화 기록을 연결하기 위한 값이다. ID만으로 규칙을 수정하지 않는다.
