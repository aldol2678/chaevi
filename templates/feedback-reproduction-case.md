# 채비 익명화 재현 사례

상태: `DRAFT / UNVERIFIED`

> 이 문서는 피드백 신호를 재현 가능한 규칙 사례로 승격할 때 사용한다. 사용자가 명시적으로 공유를 승인한 익명화 입력만 기록한다.

## 1. 사례 정보

| 필드 | 값 |
|---|---|
| `caseId` | `[예: CHAEVI-FR-001]` |
| `capturedAt` | `[ISO 8601 또는 YYYY-MM-DD]` |
| `mode` | `[route / discover]` |
| `reason` | `[wrong_category / wrong_order / wrong_ai_model / wrong_plugin / unclear_result]` |
| `rulesVersion` | `[예: v0.3]` |
| `sourceFeedbackIds` | `[관련 ID 목록 또는 빈 배열]` |
| `sensitiveDataRemoved` | `[true / false]` |
| 검토 상태 | `[SIGNAL / REPRODUCIBLE / TESTED / RELEASE CANDIDATE]` |

## 2. 익명화·공유 확인

- [ ] 사용자가 이 입력을 프로젝트 검증에 사용하는 것을 승인했다.
- [ ] 이름, 이메일, 계정 ID, 전화번호, 주소를 제거하거나 대체했다.
- [ ] 토큰, 비밀번호, 인증 코드, 비공개 링크를 제거했다.
- [ ] 개인 파일명과 비공개 프로젝트명은 판정에 필요하지 않으면 일반 표현으로 바꿨다.
- [ ] 익명화가 판정에 필요한 핵심 의도를 바꾸지 않았다.
- [ ] 원본 입력은 이 파일이나 저장소에 남기지 않았다.

하나라도 확인할 수 없으면 사례 상태를 `SIGNAL`로 유지하고 재현 입력을 기록하지 않는다.

## 6. 재현 절차

1. 기준 브랜치와 커밋을 `[값]`으로 맞춘다.
2. 규칙 버전 `[값]`을 확인한다.
3. 모드를 `[route / discover]`로 선택한다.
4. 위 익명화 입력을 실행한다.
5. 실제 결과를 기대 결과와 비교한다.

## 7. 재현 결과

- 재현 여부: `[PASS 재현됨 / FAIL 재현 안 됨 / BLOCKED]`
- 반복 횟수: `[예: 3/3]`
- 증거: `[화면 결과, 테스트 출력 또는 근거]`
- 원인 후보: `[키워드 충돌, 우선순위, 점수, 단계 축약 등]`

재현되지 않으면 코드 변경 후보로 승격하지 않는다.
